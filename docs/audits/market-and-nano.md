## 旧版地摊数据结构

旧版将公共资料和个人字段混在同一条记录中：

```ts
interface LegacyPriceRecord {
  name: string;
  resType: number;
  resLevel: number;
  price: number;
  coupon: number;
  focus: boolean;
  materialList: Array<{
    id: number;
    name: string;
    num: number;
    exchangeable: boolean;
  }>;
}
```

主要结构风险：

- 使用可变的中文名称作为实体主键和配方外键。
- 公共配方、用户售价、关注状态混合存储，公共更新容易覆盖个人数据。
- `exchangeable` 的名称不能准确表达实际计算语义。
- 没有数据版本、稳定 ID 或实体迁移映射。

新版将公共实体、用户覆盖和派生计算拆分，并使用不可变稳定 ID。

## 已还原地摊算法

### 材料成本

原材料类型为 `resType <= 4`：

```text
券成本 = 物品采集券
金币成本 = 0
```

加工品递归遍历材料：

- `exchangeable = true`：展开该材料的配方，累计券成本和金币成本。
- `exchangeable = false`：不展开配方，直接按材料售价计入金币成本。

### 售出收益

```text
税后收入 = round(售价 × (1 - 税率))
实际收益 = 税后收入 - 金币成本
券收益比 = round(实际收益 ÷ 券成本 × 100, 2)
```

旧版在售价或券成本为零时将券收益比置零。

### 半成品爆率

旧版只对 `resType = 5` 应用半成品爆率：

```text
爆率收益 = round(
  售价 × (1 - 税率) × (100 + 爆率百分比) ÷ 100 - 金币成本,
  2
)
```

## 已修复的旧版缺陷

### 缺少配方循环保护

旧版递归函数没有访问状态。如果用户新增 `甲 -> 乙 -> 甲`，会无限递归并最终产生调用栈溢出。新版计算核心会返回带完整路径的 `RECIPE_CYCLE` 数据错误。

### 缺失物品返回错误价格

旧版在查找物品时，会在比较名称前不断覆盖临时 `price`。如果名称不存在，函数可能返回列表最后一项的价格，而不是报告引用缺失。新版遇到缺失实体会返回 `MISSING_ITEM`，禁止生成静默错误结果。

### 重名实体无保护

旧版按名称线性查找，重名时取第一条数据。新版迁移阶段会检测重复实体并停止导入，正式模型改用稳定 ID。

## 纳米算法初步还原

- 纳米 1/2/3 使用最小值、最大值和平均值存储。
- 展示计算使用平均值。
- 券比：`纳米平均值 ÷ 券成本`，保留 5 位小数。
- 直购比：`纳米平均值 ÷ 售价`，保留 5 位小数。
- 旧版使用常量 `750` 计算纳米 2 对应的专研次数。
- 旧版存在将金币成本按 `0.425` 转换为券成本的特殊分支。

`750` 和 `0.425` 的游戏规则含义、适用版本及特殊分支的一致性仍需继续核对。它们不会在缺少依据时直接写成不可配置常量。
